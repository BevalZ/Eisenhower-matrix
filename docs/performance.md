# 性能机制与回归检查

基线：`b373c96`，优化日期：2026-10-25。数据均为生成的测试任务，不读取真实任务库。保持 SQLite 持久化、同步冲突规则、任务排序和撤销语义。

## 已落实的机制

| 路径 | 机制 | 约束 |
| --- | --- | --- |
| 任务刷新 | 同一时刻最多一个读取；同步事件合并；读取期间再次失效只补一次最新读取 | 拖拽和写入期间暂停应用快照，过期结果丢弃；失败后可以重试 |
| 任务状态 | 按 ID 复用对象；无变化且顺序相同时复用数组 | 避免无变化刷新重新排序、分组和更新所有卡片 |
| 批量移动 | 惰性 ID 索引，查找从 O(任务数 × 移动数) 变为 O(任务数 + 移动数) | 写入顺序由前端队列保持，后端在工作线程执行；原有回滚保留 |
| 拖拽 | 二分查找落点和完成状态分界；缓存节点列表与过滤后的任务列表 | DOM 更新后清缓存；每帧读取 O(log n) 个卡片位置，不缓存会变化的坐标 |
| 看板布局 | 网格行使用 `minmax(0, 1fr)`，设置 `min-height: 0` | 大列表在象限内滚动，避免整个网格被内容撑高 |
| 初始加载 | 设置、统计、向导、编辑按需加载；悬浮球独立入口 | 悬浮球不实例化任务状态、不订阅任务同步、不拉取任务列表 |
| 生命周期 | 异步事件注册归属组件作用域；晚到的注册也会释放 | 关闭组件后忽略回调；隐藏主窗口延后远端刷新和暂停提醒定时器 |
| 截止提醒 | 去重缓存清理已完成、已删除和旧截止时间的记录 | 最多保留当前未完成且有截止时间任务的两个状态；首次成功加载前不清缓存；超过 500 项也不重复提醒 |
| SQLite | 导入、排序、恢复复用预编译语句；同步缓存语句且只读冲突判断元数据 | 保留事务原子性、时间戳与设备 ID 决胜、旧协议保留本地截止时间 |
| 数据库锁 | 同步每 2000 条释放一次互斥锁；JSON 导出序列化在锁外 | 让前台命令有机会获得锁，不保证线程调度公平性 |
| UI 线程 | 任务 CRUD、统计、设置读取、导入导出使用 `spawn_blocking` | SQLite 与系统凭据读取不会占用窗口线程 |
| 查询 | 活跃任务部分索引匹配 `done ASC, priority DESC, id ASC` | 看板查询无需临时排序；删除墓碑不进入索引 |

## 测量结果

Windows、Node 26.1.0、Vue 3、Vite 5.4.21；浏览器为 Edge。耗时是单机合成基准，不代表所有设备；硬性检查使用操作数量、对象身份与资源预算。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 1 万任务、连续 10 次无变化刷新（含 Vue 排序依赖，首次记录） | 630.78 ms，重新排序 10 次 | 186.95 ms，重新排序 0 次 |
| 5000 项批量排序的 ID 读取 | 12,502,500 次（原逐条扫描） | 5000 次（实际 store 测量） |
| 1 万卡片的落点几何读取 | 10,000 次 | 最多 14 次 |
| 主窗口初始 JS，含所有静态依赖，磁盘字节 | 165,610 B | 134,050 B（减少约 19%） |
| 主窗口初始 CSS | 32,437 B | 17,178 B（减少约 47%） |
| 悬浮球初始 JS | 165,610 B | 101,776 B（减少约 39%） |
| 悬浮球收到 100 次事件后的任务读取 | 100 次 | 0 次 |
| 悬浮球收到事件后的 JS 堆，1 万任务夹具、强制 GC 后 | 3,818,836 B | 3,120,756 B |
| 1000 条任务的网格高度，1100 × 750 窗口 | 43,693 px | 受窗口高度约束，四象限各自滚动 |

JS 堆测量包含测试夹具；不是 Tauri 进程 RSS 或 WebView2 总内存。不能把约 0.7 MB 的差值推广为所有设备的内存收益。悬浮球原生 WebView 仍由 Tauri 创建，本轮减少的是其加载与任务驻留开销。

## 可复跑的检查

```sh
npm test
npm run perf
npm run perf:bundle
cd src-tauri
cargo test
```

`npm test` 已包含操作数量与资源生命周期回归；`npm run perf` 单独输出合成基准。包体积检查遍历 Vite manifest 的静态依赖，主窗口预算为 JS 140 KiB / CSS 24 KiB，悬浮球为 JS 110 KiB / CSS 10 KiB；超过预算会失败。CI 在前端构建后自动运行此检查。不要仅为了让 CI 通过就抬高预算。

测试扫描限定 `src`，避免 `output/` 中的历史源码副本被重复计入。临时基线保留在已忽略的 `output/performance/`（自动审批阻止了递归清理），不影响构建与测试。

浏览器验证使用 Tauri IPC 夹具，覆盖 1000 条任务、事件风暴、统计页往返、设置/向导按需加载、跨象限拖拽、键盘移动及编辑：

```sh
# 先 npm run build；在独立终端保持服务运行
node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 1421

npx --package @playwright/cli playwright-cli -s=performance open about:blank --browser msedge
npx --package @playwright/cli playwright-cli -s=performance run-code --filename scripts/performance/browser-setup.js
npx --package @playwright/cli playwright-cli -s=performance run-code --filename scripts/performance/browser-check.js
npx --package @playwright/cli playwright-cli -s=performance close
```

运行前创建 `output/playwright/`，截图写入该目录（已忽略）。浏览器检查等待入场动画结束后才统计 DOM 变更，避免把动画结束误算成刷新工作。`browser-compare-ball.js` 可比较 1422 端口的基线构建和 1421 端口的当前构建，并检查 Android UA 下旧悬浮球窗口标签仍进入主界面；需先运行 setup 安装夹具。

## 验证范围与后续

- 前端：61 项测试通过，类型检查、生产构建、包体积预算通过。
- Edge 生产构建：100 次同步事件只读取一次，稳定看板 DOM 变更为 0；统计页往返 4 次后监听恢复到 1；拖拽、键盘移动、编辑和弹窗通过。
- Rust：本机 `cargo test --ignore-rust-version` 因缺少 MSVC `link.exe` 无法链接。使用现有依赖产物对**本轮全部 Rust 源码和测试代码**执行 `rustc --test --emit=metadata` 已通过；这仅验证类型，不代表 Rust 测试已执行。完整 Rust 测试仍需配置完整的 MSVC 工具链或使用仓库 CI，本轮未触发远程发布。
- 本轮新增 Rust 回归检查覆盖活跃索引查询计划及同步时间戳平局。既有事务回滚、旧协议截止时间和超过一批的同步测试继续保留。
- 本机未测 Android 真机、原生 WebView2 总内存和真实磁盘写入延迟；未修改持久化耐久性设置。
- 所有活跃任务仍然挂载为 DOM。若后续需要长期显示数万条活跃任务，应进一步实施可变高度虚拟列表，同时验证触屏、键盘焦点及拖拽落点。同步传输仍是全量快照，分页/增量协议属于后续工作。
